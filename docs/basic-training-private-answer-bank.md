# حماية مفاتيح إجابات التدريبات الأساسية — خطة النشر

**الحالة:** تطبيق جزئي في الفرع التجريبي، لا يجوز الدمج أو التفعيل الإنتاجي بعد.

## تغييرات تم تنفيذها
- حذف ملفات `basic-training-01-new-quiz.json` إلى `basic-training-08-new-quiz.json` من رأس الفرع العام.
- حذف ترحيل `20261013_basic_training_approved_160_questions.sql` الذي كان يتضمن الإجابات الصحيحة كلها في مستودع عام.
- معاينة أسئلة القائد في `basic-training.js` تقرأ من `basic_training_admin_revision` فقط، بعد تحقق الخادم من جلسة القائد ودوره.

## خطة الاعتماد دون تكاليف إضافية (قرار المستخدم)
**لا إنشاء فرع Supabase مدفوع أو مشروع جديد أو خدمات مدفوعة.** نستخدم مشروع Supabase الحالي وVercel/GitHub المتوفرين، ضمن حدود الاستخدام الحالية.

### المرحلة الحالية: دون تعديل بيانات الإنتاج
1. تشغيل استعلام `scripts/basic-training-readonly-preflight.sql` أو ما يماثله لفحص التوافق من دون أي تغييرات.
2. إجراء اختبارات JS ثابتة ومُحاكاة عن طريق `npm run build` و`node scripts/test-basic-training-contract.js` دون قاعدة حقيقية. النجاح هنا ليس بديلًا عن تكامل قاعدة البيانات.
3. مراجعة نصوص ترحيلات SQL بعناية، والتأكد من أنها تنشئ جداول `basic_training_*` مستقلة ولا تغير أو تمس `training_*` القديمة.
4. معاينة واجهتي القائد والعضو فقط على Vercel Preview.
5. عدم تشغيل ترحيلات DDL أو استيراد البيانات أو إنشاء حسابات تجريبية في قاعدة الإنتاج حتى حصول موافقة صريحة مستقلة بعد مراجعة خطة التراجع والنسخ الاحتياطي.

### عند الحصول على موافقة منفصلة لتركيب النظام في قاعدة البيانات الحالية
1. تحقّق من استمرارية وسلامة النسخة الاحتياطية والقدرة على التراجع قبل أي عمليات كتابة.
2. نفّذ `20261013_basic_training_persistence_90_80.sql` لإنشاء الجداول الجديدة.
3. نفّذ `20261013_basic_training_private_import_function.sql`؛ الاستيراد الحساس يستخدم صلاحيات خدمة محمية، ولا تُعرض مفاتيح الإجابات للأعضاء.
4. استورد بنك 8 تدريبات و160 سؤالًا من مصدر خاص خارج GitHub العام. يوجد سكربت محلي اختياري للتحويل (`prepare-private-basic-training-bank.js`) لكن لا يُستخدم مصدر تاريخي مسرّب باعتباره سرًا جديدًا.
5. نفّذ `20261013_basic_training_leader_member_profile.sql` ثم `20261013_basic_training_revision_admin.sql` بعد نجاح استيراد البيانات.
6. اختبر أعضاءً تجريبيين مخوّلين مع 90% مشاهدة و16/20 للنجاح و15/20 للرسوب، وعدم كشف مفتاح الإجابات، وصلاحيات القائد، وتسجيل إصدار الاختبار.
7. قارن عدد السجلات في الجداول القديمة قبل وبعد التركيب؛ لا تتجاوز الموارد الحالية أو تشغّل عمليات مدفوعة.

**ملاحظة:** أداة الاستيراد `import-private-basic-training-bank.js` مقيدة عمدًا بالبيئات المعزولة؛ لا تحاول تجاوز حمايتها أو تزويدها ببيانات اعتماد الإنتاج. التنفيذ من SQL Editor سيستلزم خطة إدخال خاصة معتمدة عندما نصل إلى هذه المرحلة.

**معايير الأمان:** لا تُرسل `service_role` للدردشة أو المتصفح أو GitHub. لا تُعرض الإجابات الصحيحة في استجابة اختبار العضو. حد المحاولات 6 خلال ساعة. يرفض الخادم تسليم اختبار من إصدار إلى إصدار مختلف عند التصحيح، ويمنع تعديل فيديو أو مدته إذا وجدت سجلات مشاهدة محفوظة.

## مهم
ترحيل بيانات الأسئلة المعتمد لم يعد ضمن HEAD للفرع العام عن قصد. **هذا يمنع تركيب النظام كاملًا من المستودع العام وحده** حتى توفّر نسخة خاصة من بيانات الأسئلة. المادة الأصلية باقية في تاريخ Git السابق، لكنها ليست مصدرًا آمنًا للاستخدام المستقبلي. لا تنقل النسخة التاريخية كما هي إلى الإنتاج باعتبارها سرية.

لم نغيّر Supabase الإنتاجي أو `main`.

**ملاحظة تدقيق:** توجد نسخ من ملفات الإجابات القديمة في فرع GitHub عام آخر، وكذلك في تاريخ Git؛ يُمنع وصف المفاتيح القديمة بأنها سرية قبل إعادة اعتماد بنك أسئلة محدث.
